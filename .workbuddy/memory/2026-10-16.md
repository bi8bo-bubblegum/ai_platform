## 16:50 IDE 爆红问题：配置类改 JavaBean 风格（用户提议「直接在 properties 中写」）

- **现象**：用户报 yml 里 `temperature` 无补全 + 爆红
- **根因（实测，非推断）**：Spring 配置元数据处理器**不递归进 Map 的值类型，也不认 record 的访问器**
  - `Map<String, ModelSpec>` → 元数据只 1 条 `ai.models | Map<...>`

- **最终形态**：`ModelProperties`（JavaBean，含嵌套 `ModelSpec`，默认值写字段上）→ 不再需要 `ModelSpec.java`、`GenerateDefaultsConfig`、additional json；`ModelSpec` 必填校验移到 `ModelRegistrar.require(...)`（报错带模型名，实测消息：`模型 fast 缺少 api-key（配 ai.fast.api-key）`）

**第 4 章（50 号）实测事实**
- `io.agentscope.core.tool.Tool` **本身是注解接口**（extends Annotation），属性：name/description/strict/readOnly/concurrencySafe/externalTool/stateInjected/returnDirect/dangerousFiles/dangerousDirectories/converter；`description` 是 requireNonNull

- **三条返回路径实测**：正常 → `state=RUNNING`（不是 SUCCESS！）；抛异常 → `state=ERROR` + 文本 `Error: Tool execution failed: <原因>`（框架接住，不上抛）；抛 `ToolSuspendException` → `state=RUNNING` + `isSuspended=true` + `metadata={agentscope_suspended=true}`

**第 5 章（51 号）实测事实**
- `PermissionBehavior` **四个**（文档说三态漏了 `PASSTHROUGH`）；`PermissionMode` 五个：DEFAULT/ACCEPT_EDITS/EXPLORE/BYPASS/DONT_ASK
- **五模式矩阵（实测）**：DEFAULT 全 ASK；ACCEPT_EDITS 只读 ALLOW/非只读 ASK；EXPLORE 只读 ALLOW/非只读 **DENY**；BYPASS 全 ALLOW；**DONT_ASK 全 DENY**（拒绝理由 `User is not available to answer permission prompts`——不是"免问"！）
- **判定链路（反编译 checkPermission）**：checkDenyRules → checkAskRules → toolCheckPermissions → switchIfEmpty(模式兜底)。**没有 checkAllowRules**——allow 规则是 HITL 产物（`getSuggestedRules()` 里 `source=suggested`），不是配置项
- **规则的三个坑**：① bucket key 必须是 `toolName`（`rulesFor(denyRules, tool.getName())`，传 "safety" 静默失效）；② **`ruleContent` 只能填 null**（非 null 全部不命中，因为 `ruleMatches` 直接调 `ToolBase.matchRule`，而后者实现就是 `return ruleContent == null`）；③ `ToolBase.matchRule` 名不副实，别在业务里调
- HITL 协议（javap）：`RequireUserConfirmEvent(replyId, agentId, List<ToolUseBlock>)` / `UserConfirmResultEvent(replyId, agentId, List<ConfirmResult>)` / `ConfirmResult(confirmed, toolCall, rules, reason)`；拒绝 → `ToolResultState.DENIED`
