## AI 平台架构思路（首轮对齐，未写代码）

**工程现状**：`/Users/best/project/ai_platform` 只有一个裸 `pom.xml`（groupId `com.best`，Java 17，无 parent / 无 Spring Boot / 无依赖管理），`src/` 为空。

**用户诉求**：各类助手作为独立微服务放在本工程，另加一个 ai-common 模块统一提供 Model 能力。

**给出的核心结论**

1. 真正的分歧点不是"要不要 common"，而是 Model 是「SDK 直连」还是「独立服务出口」。
   推荐：**契约统一 + 实现可插拔**——ai-common-model 只定义 `ChatClient` / `EmbeddingClient` / `RerankClient` 接口，
   提供 `direct`（直连厂商）与 `remote`（走 ai-model-service）两套实现，用 `ai.model.mode` 切换，业务代码零改动。
2. 模块分层：`ai-gateway` → `assistant-*` → `ai-model-service` → `ai-common(core/model/mcp/agent)` → Nacos / Redis / MySQL / Sentinel / SkyWalking。
3. 引入**逻辑模型名**（`chat.default` / `chat.reason` / `embed.default`），路由表放 Nacos，切模型零发版。
4. `ai-common` 是编译期 jar 依赖层，不是运行期调用链路中的一跳。
5. 助手共性（Agent 循环、工具注册、会话存储）抽到 `ai-common-agent`，每个助手服务只写「定义 + 工具」。
6. **明确提醒**：不要一上来拆 5 个微服务，先单体跑通 1 个助手 + Model 抽象；出现第二、三个助手且资源画像不同时再拆。
