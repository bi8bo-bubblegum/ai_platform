## 2. ModelProbeController 完整代码

**文件路径：`/Users/best/project/ai_platform/ai-agentscope/src/main/java/com/best/ai_agentscope/ch02_model/ModelProbeController.java`**

```java
package com.best.ai_agentscope.ch02_model;

import com.best.ai_agentscope.model.ModelRegistrar;
import io.agentscope.core.agent.RuntimeContext;
import io.agentscope.core.message.ContentBlock;
import io.agentscope.core.message.TextBlock;
import io.agentscope.core.message.UserMessage;
import io.agentscope.core.model.ChatUsage;
import io.agentscope.core.model.GenerateOptions;
import io.agentscope.core.model.Model;
import io.agentscope.core.model.ModelRegistry;
import io.agentscope.core.model.ToolSchema;
import io.agentscope.harness.agent.HarnessAgent;
import java.util.ArrayList;
import java.util.LinkedHashMap;
import java.util.List;
import java.util.Map;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.PostMapping;
import org.springframework.web.bind.annotation.RequestParam;
import lombok.extern.slf4j.Slf4j;
import org.springframework.web.bind.annotation.RestController;

@Slf4j
@RestController
public class ModelProbeController {

    private final ModelRegistrar registrar;
    private final HarnessAgent.Builder agentBuilder;

    public ModelProbeController(ModelRegistrar registrar) {
        this.registrar = registrar;
        // 容错 agent：fast 主 + strong 备，全部按名引用（注册表解析）
        this.agentBuilder = HarnessAgent.builder()
                .name("fault-tolerant")
                .agentId("fault-tolerant")
                .sysPrompt("你是一个用来验证模型容错的助手，回答保持简短。")
                .model("fast")
                .fallbackModel("strong")
                .maxRetries(2)
                .failoverListener((failed, error) ->
                        log.warn("[failover] 主模型 {} 失败（{}），切换备用模型",
                                failed.getModelName(), error.getMessage()));
    }

    /** 能力报告：遍历注册表，让每个模型自报支持什么 */
    @GetMapping("/model/capabilities")
    public Map<String, Object> capabilities() {
        Map<String, Object> result = new LinkedHashMap<>();
        for (String name : registrar.names()) {
            Model model = registrar.byName(name);
            Map<String, Object> info = new LinkedHashMap<>();
            info.put("modelName", model.getModelName());
            info.put("contextWindowSize", model.getContextWindowSize());
            info.put("nativeStructuredOutput", model.supportsNativeStructuredOutput());
            info.put("nativeStructuredOutputWithTools",
                    model.supportsNativeStructuredOutputWithTools());
            result.put(name, info);
        }
        return result;
    }

    /** 模型层直连：绕过 Agent，看最原始的流式响应和 token 用量 */
    @PostMapping("/model/ask")
    public Map<String, Object> ask(@RequestParam String message) {
        Model model = ModelRegistry.resolve("fast");
        StringBuilder text = new StringBuilder();
        List<ChatUsage> usages = new ArrayList<>();
        model.stream(List.of(new UserMessage(message)), List.<ToolSchema>of(),
                        GenerateOptions.builder().build())
                .doOnNext(chunk -> {
                    for (ContentBlock block : chunk.getContent()) {
                        if (block instanceof TextBlock tb) {
                            text.append(tb.getText());
                        }
                    }
                    if (chunk.getUsage() != null) {
                        usages.add(chunk.getUsage());
                    }
                })
                .blockLast();
        Map<String, Object> result = new LinkedHashMap<>();
        result.put("text", text.toString());
        result.put("chunksWithUsage", usages.size());
        if (!usages.isEmpty()) {
            ChatUsage last = usages.get(usages.size() - 1);
            result.put("inputTokens", last.getInputTokens());
            result.put("outputTokens", last.getOutputTokens());
            result.put("totalTokens", last.getTotalTokens());
        }
        return result;
    }

    /** 走容错 agent：主模型坏 → 重试 → 切备用模型 */
    @PostMapping("/model/agent-ask")
    public String agentAsk(@RequestParam String sessionId, @RequestParam String message) {
        try (HarnessAgent agent = agentBuilder.build()) {
            RuntimeContext ctx = RuntimeContext.builder()
                    .userId("alice")
                    .sessionId(sessionId)
                    .build();
            return agent.call(new UserMessage(message), ctx).block().getTextContent();
        }
    }
}
```

**逐段讲为什么**：

| 代码 | 为什么这样写 |
|---|---|
| 构造器注入 `ModelRegistrar` | 注册表 bean。**注意没有注入 `Model`**——模型不在 Spring 容器里（见 §3②），这是注册表形态的形态特征。生成参数也不在这里配了，它们在 yml 的模型规格里（§3⑤） |
| `.model("fast")` / `.fallbackModel("strong")` | 两个都**按名引用**。切换主/备模型只需要改这两个词，或在 yml 里改 `fast`/`strong` 的 `model-name`——**换模型不动 Java 代码**，这是注册表最大的价值 |
| 容错 builder 在**构造器里建、不注册成 bean** | 第 1 章已经有一个 `HarnessAgent.Builder` bean 了。再注册第二个同类型 bean，第 1 章的控制器按类型注入就会歧义。**「有几个使用方」判据**：只服务本章三个探针 → 就地构造 |
| `/model/capabilities` 遍历 `registrar.names()` | `ModelRegistry` 只有 `resolve/canResolve`，**没有枚举接口**（javap 实测），所以能力报告要靠 registrar 自己维护的名册 |
| `model.getContextWindowSize()` 等四个方法 | `Model` 接口的**默认方法**（javap 实测）。**让模型自报能力，比翻文档可靠**——尤其你的端点背后是谁还不确定 |
| `/model/ask` 用 `ModelRegistry.resolve("fast")` | 演示「不经过 builder 也能拿到模型」。这是框架注册表的公开入口，等价于 ai-common 的 `ModelRegister.get(profile)` |
| `List.<ToolSchema>of()` 显式泛型 | `List.of()` 推不出类型参数，编译不过 |
| `chunksWithUsage` | ⚠️ **本章最重要的探针**。OpenAI 协议流式响应默认**不返回 usage**（需 `stream_options.include_usage`，还要网关透传）。你在项目里踩过的「流式 token 计量拿不到数」，这里能直接看到真相 |
| `failoverListener` 里只 `log.warn` | javap 实测签名 `onFailover(Model, Throwable)`。它跑在失败路径上，**必须非阻塞**，抛异常会掩盖真实错误。生产形态是打点上报 |

## 3. 三个必须建立的心智模型

**① 注册表是三段链路，每一段都能查。**

```
yml: ai.models.fast.{base-url,api-key,model-name}
  → ModelProperties 绑定（Map<name, ModelSpec>）      ← 坑：绑定路径 = prefix + 字段名 + key
  → ModelRegistrar 构造 OpenAIChatModel 实例          ← ModelSpec 校验在这里生效
  → ModelRegistry.register("fast", model)             ← 框架的静态注册表
  → .model("fast") / ModelRegistry.resolve("fast")    ← 两条取用路径
```

启动日志的 `[model-registry] 已注册模型：[strong, fast]` 就是第二段的出口。**这条链上任何一段断了，症状都是 `Cannot resolve model: "fast"`**——排障时按段落查：yml 路径 → Spec 校验 → 注册日志 → 引用名拼写。

⚠️ **两处实测出来的静默失效**（都写进 46 号排障表了，这里再点一次）：
- **配置类写法决定 IDE 是否爆红**：`Map<String, X>` 或 record 嵌套都不生成子属性的元数据（正解 = JavaBean + 具名字段，实测见 46 号 §7.3）。老写法还会踩「Map 绑定路径多一层→静默空 map」的坑。
- **`.model(String)` 是立即解析**：builder 配置方法调用时就查注册表，不是等到 `build()`。所以注册必须先完成——第 1 章的 `ModelRegistrar` 参数注入就是在保这个序。

**② 模型**不做** Spring bean，这是有意的。**

注册表形态下，Spring 容器里**没有** `Model` 类型的 bean。后果很直接：

- `@Autowired Model` 会失败。取模型只有两条路：builder 里写字符串（`.model("fast")`），或 `registrar.byName("fast")` / `ModelRegistry.resolve("fast")`
- 为什么这样更好：一个模型会被多个 agent 共用（`fast` 现在就被 note-taker 和 fault-tolerant 同时引用）。bean 化的话，多个模型 bean + 按类型注入 = 处处 `@Qualifier`；而注册表把「名字 → 实例」这层映射显式化，注入点只依赖名字
- 这也是 ai-common 的形态：`ModelRegister` 是静态注册表，`ChatModel` 不是按类型注入的

**③ 容错三件套是三件事，别混。**

| 机制 | 语义 | 本章配置 |
|---|---|---|
| `maxRetries(n)` | **同一模型**失败后重试 n 次 | `.maxRetries(2)` |
| `fallbackModel(m)` | 主模型**连续失败后换模型**（按名解析，同样是立即的） | `.fallbackModel("strong")` |
| `failoverListener(l)` | 切换时**观察**（非阻塞） | `log.warn` 版 |

简单「主→备」回退用 builder 三件套就够，**不要**自己写 `onModelCall` 中间件做重试——第 12 章会讲为什么（中间件是洋葱模型，自己做重试要处理订阅/取消/线程，那是拿业务代码换框架已经做对的事）。

**④ 追问：`OpenAIChatModel.builder().build()` 到底产出什么？（实测矩阵）**

| 形态 | `build()` | 调用时 |
|---|---|---|
| `builder().build()` 全裸 | ❌ **当场抛 `NullPointerException: modelName must be set`** | — |
| `builder().modelName("gpt-4.1-mini")` | ✅ | 空 key 也照样发请求 → 服务端 **401** |
| `+ .apiKey("sk-...")` | ✅ | 假 key → 401；**不给 baseUrl 时默认打 `api.openai.com/v1`** |
| `+ .baseUrl(...)` 三样全给 | ✅ | 同上 |

三个结论：

1. **`modelName` 是构建期唯一强制的字段**（`Objects.requireNonNull`，报错可读）。不存在「空壳对象留到调用期才炸」。
2. **builder 路线不读环境变量**。实测把 `AI_API_KEY` / `OPENAI_API_KEY` 全摘掉，只给 modelName，请求照发（空 key），吃 401。所以注册表里 `api-key` 必须显式来自 yml —— **这正是 `ModelSpec` 要在启动期校验 api-key 的原因**。
3. **apiKey 缺失的报错离原因很远**（401 而不是「缺 key」），所以校验要前置到启动期。

**日志规范（本章及后续通用）**：应用组件（`@Component` / `@RestController`）一律用 Lombok `@Slf4j`，不出现 `System.out`（46 号 pom 已加 lombok 依赖）。**下面的探针是例外**——它们是独立 `main`（`mvn exec:java` 跑一次看结果），输出的是「程序结果」而不是应用运行日志，`System.out` 更直接（没有时间戳/类名前缀，长 JSON 好读）。要给探针也加 `@Slf4j` 不影响功能，看个人习惯。

## 3.5 生成参数为什么要写进注册表（含请求体实测）

`temperature` / `max-tokens` / `parallel-tool-calls` 现在写在 **yml 的模型规格里**（46 号 §6），由 `ModelRegistrar` 烤进模型实例。三个问题必须先回答清楚：

**问题一：模型上烤进的参数，调用方不传时生效吗？** 生效。
**问题二：调用方显式传值时谁赢？** 调用方赢，而且是**按字段覆盖**——没传的字段仍用模型的默认。
**问题三：怎么证明？** 用本地假端点截获真实请求体。实测结果：

| 场景 | 抓到的请求体 |
|---|---|
| 模型烤进 `temperature=0.9, maxTokens=123`；调用方传**空** options | `{"model":"probe-model","messages":[...],"stream":false,"temperature":0.9,"max_tokens":123}` |
| 同上，但调用方**显式**传 `temperature=0.1` | `{"...","temperature":0.1,"max_tokens":123}` ← 0.9 被顶掉，**max_tokens 保留** |

结论：**yml 定默认、代码按需覆盖**这条链是通的，而且覆盖粒度是字段级的。

⚠️ 一个细节：现在三项参数的**默认值用 `@DefaultValue` 标在 `ModelSpec` 的构造参数上**（0.2 / 2048 / false），注册器总是把这三个值烤进模型实例——所以「请求体里没有 temperature」这种情况不会再出现，yml 里也没必要重复写默认值。

**探针代码**（本地假端点 + 请求体截获，这个手法第 4 章验证工具调用、第 5 章验证权限都会再用）：

```java
package com.best.ai_agentscope.probe;

import com.sun.net.httpserver.HttpServer;
import io.agentscope.core.message.UserMessage;
import io.agentscope.core.model.GenerateOptions;
import io.agentscope.core.model.ToolSchema;
import io.agentscope.extensions.model.openai.OpenAIChatModel;
import java.io.OutputStream;
import java.net.InetSocketAddress;
import java.nio.charset.StandardCharsets;
import java.util.List;
import java.util.concurrent.atomic.AtomicReference;

public class GenerateOptionsProbe {

    public static void main(String[] args) throws Exception {
        AtomicReference<String> captured = new AtomicReference<>();

        HttpServer server = HttpServer.create(new InetSocketAddress(0), 0);
        server.createContext("/v1/chat/completions", exchange -> {
            captured.set(new String(exchange.getRequestBody().readAllBytes(),
                    StandardCharsets.UTF_8));
            byte[] resp = ("{\"id\":\"probe\",\"object\":\"chat.completion\",\"model\":\"probe\","
                    + "\"choices\":[{\"index\":0,\"message\":{\"role\":\"assistant\","
                    + "\"content\":\"ok\"},\"finish_reason\":\"stop\"}],"
                    + "\"usage\":{\"prompt_tokens\":1,\"completion_tokens\":1,\"total_tokens\":2}}")
                    .getBytes(StandardCharsets.UTF_8);
            exchange.getResponseHeaders().add("Content-Type", "application/json");
            exchange.sendResponseHeaders(200, resp.length);
            try (OutputStream os = exchange.getResponseBody()) {
                os.write(resp);
            }
        });
        server.start();
        int port = server.getAddress().getPort();

        OpenAIChatModel model = OpenAIChatModel.builder()
                .apiKey("sk-probe")
                .baseUrl("http://localhost:" + port + "/v1")
                .modelName("probe-model")
                .stream(false)                       // 非流式，假端点好回
                .generateOptions(GenerateOptions.builder()
                        .temperature(0.9).maxTokens(123).build())
                .build();

        model.stream(List.of(new UserMessage("hi")), List.<ToolSchema>of(),
                        GenerateOptions.builder().build())      // 调用方传空
                .blockLast();
        System.out.println("空 options 时: " + captured.get());

        model.stream(List.of(new UserMessage("hi")), List.<ToolSchema>of(),
                        GenerateOptions.builder().temperature(0.1).build())
                .blockLast();
        System.out.println("显式 0.1 时: " + captured.get());

        server.stop(0);
    }
}
```

## 7. 容易写错 / 被改坏的 6 个点

1. **配置类写成 Map 或 record 嵌套**——处理器不生成子属性元数据，IDE 爆红；Map 还会踩绑定路径多一层的静默空 map。正解：JavaBean + 具名字段（46 号 §7.3）。
2. **忘了 `.model("fast")` 是立即解析**——注册必须先完成。删掉 `ModelRegistrar` 参数会导致 bean 创建顺序不定，随机抛 `Cannot resolve model`。
3. **`defaultOptions` 不存在**——文档示例是它，2.0.4 实际是 `generateOptions`。**动作固定下来：文档给的 builder 方法名，javap 一下再写。**
4. **自己 new 一个 Model 塞进 builder**——绕过注册表就失去了「按名换模型」的能力；而且多一个实例就多一份连接配置，容易和注册表不一致。要在注册表里加，改 yml。
5. **`failoverListener` 里做重活**——它在失败路径同步跑，阻塞或抛异常会掩盖真实错误。
6. **`maxRetries` 配大**——网关限流场景下，5 次重试 = 一次故障放大成 6 次请求。2–3 合理，配合 fallback 兜底。
7. **别再把生成参数写回 `@Bean`**——`temperature` 等已经属于「模型规格」（yml `ai.<name>.*`）。再搞一个 `GenerateOptions` bean 让各章 builder 引用，就有两个层级在打架（模型烤一套、agent builder 一套），谁赢要读框架实现才知道。**一个来源原则**：模型层的默认写在注册表，单次调用要特殊值就在 `call(msgs, options)` 里传。
