## 先看清：这次有一处**行为变化**，不是纯搬家

你现在的 `AiCommonAutoConfiguration` 上挂着**类级**条件：

```java
@ConditionalOnProperty(prefix = "ai.chat", name = "enabled", havingValue = "true", matchIfMissing = true)
public class AiCommonAutoConfiguration {
```

类级条件会管住**这个类里的所有 Bean**。所以现在如果配 `ai.chat.enabled: false`，不只是关掉对话模型 ——
**`EmbeddingModelRegister` 和 `AiUserContextInterceptor` 也一起没了**。

而 `TokenUsageDbAutoConfiguration` 是独立类，所以 token 台账**不受影响**。这就成了"关一半留一半"。

下面的新版本把条件**下移到具体 Bean**上，于是各管各的：

| 配置 | 影响 |
|---|---|
| `ai.chat.enabled: false` | 只关 `ChatModelRegister` + `StreamingChatModelRegister` |
| `ai.embed.enabled: false` | 只关 `EmbeddingModelRegister` |
| `ai.mcp.enabled: true` | 才装 MCP（**修好之后才真的生效**） |
| 用户上下文拦截器 | 不再被 `ai.chat` 连坐 |

**这不是我顺手改的，是 P0-1 的必然结果** —— 一旦把三个装配类合成一个，那个类级条件就必须拆掉，
否则"关 chat 会连带关掉 MCP"这种更荒谬的行为就出现了。

```java

import com.baomidou.mybatisplus.core.mapper.BaseMapper;
import com.best.ai_common.mcp.McpClientRegister;
import com.best.ai_common.metrics.TokenUsageRecorder;
import com.best.ai_common.metrics.db.AiTokenUsageMapper;
import com.best.ai_common.metrics.db.DbTokenUsageRecorder;
import com.best.ai_common.properties.ChatModelProperties;
import com.best.ai_common.properties.EmbeddingModelProperties;
import com.best.ai_common.properties.McpProperties;
import com.best.ai_common.register.ChatModelRegister;
import com.best.ai_common.register.EmbeddingModelRegister;
import com.best.ai_common.register.StreamingChatModelRegister;
import dev.langchain4j.mcp.McpToolProvider;
import org.mybatis.spring.annotation.MapperScan;
import org.springframework.beans.factory.ObjectProvider;
import org.springframework.beans.factory.annotation.Value;
import org.springframework.boot.autoconfigure.AutoConfiguration;
import org.springframework.boot.autoconfigure.condition.ConditionalOnBean;
import org.springframework.boot.autoconfigure.condition.ConditionalOnClass;
import org.springframework.boot.autoconfigure.condition.ConditionalOnMissingBean;
import org.springframework.boot.autoconfigure.condition.ConditionalOnProperty;
import org.springframework.boot.autoconfigure.condition.ConditionalOnWebApplication;
import org.springframework.boot.autoconfigure.jdbc.DataSourceAutoConfiguration;
import org.springframework.boot.context.properties.EnableConfigurationProperties;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;

import javax.sql.DataSource;

/**
 * ai-common 的<b>唯一</b>装配入口 —— .imports 里只有这一行，以后加功能都不动它。
 *
 * <p><b>为什么把 token 台账和 MCP 也收进来：</b>
 * 这三个功能原来各有一个 {@code @AutoConfiguration} 类，散在 config / metrics / mcp 三个包。
 * 于是 {@code AutoConfiguration.imports} 里要写三行 —— 而那个文件是纯文本、无编译检查，
 * 结果 {@code McpAutoConfiguration} 就被漏掉了：即使配了 {@code ai.mcp.enabled: true} 也不会生效。
 *
 * <p>收成一个类 + 嵌套 {@code @Configuration} 之后，.imports 永远只有一行，这个坑从根上没了。
 *
 * <p><b>关于 {@code after = DataSourceAutoConfiguration.class}：</b>
 * 这是必须的。嵌套的 {@code TokenUsageDbConfig} 上有 {@code @ConditionalOnBean(DataSource.class)}，
 * 而 {@code @ConditionalOnBean} 只能看到"到目前为止已经处理过的 Bean 定义"。
 * 没有这个 {@code after}，它会在 DataSource 注册之前求值 → 永远 false → 台账整块静默不装载
 * （不报错，只是 TokenUsageRecorder 这个 Bean 凭空消失）。
 */
@AutoConfiguration(after = DataSourceAutoConfiguration.class)
@EnableConfigurationProperties({
        ChatModelProperties.class,
        EmbeddingModelProperties.class,
        McpProperties.class
})
public class AiCommonAutoConfiguration {

    /**
     * 来源服务名 —— token 台账用它区分"这条用量是哪个服务产生的"。
     *
     * <p>取 {@code ai.metrics.service-name}，没配就回落到 {@code spring.application.name}，
     * 再没有就是 {@code unknown}。
     *
     * <p>用字段注入而不是方法参数：下面 chat 和 streaming 两个 Bean 都要用它，
     * 写成参数就得重复两遍这个长表达式，改的时候容易只改一处。
     */
    @Value("${ai.metrics.service-name:${spring.application.name:unknown}}")
    private String serviceName;

    // ==================================================== 模型

    @Bean
    @ConditionalOnProperty(prefix = "ai.chat", name = "enabled",
            havingValue = "true", matchIfMissing = true)
    @ConditionalOnMissingBean
    public ChatModelRegister chatModelRegister(
            ChatModelProperties properties,
            ObjectProvider<TokenUsageRecorder> recorderProvider) {
        // 注意 recorder 用 getIfAvailable() 而不是直接注入：
        // 台账那一块有 @ConditionalOnBean(DataSource.class)，没有数据源时它不存在，
        // 而这个 Bean 仍然应该能用（只是不计量）。
        return new ChatModelRegister(properties, serviceName, recorderProvider.getIfAvailable());
    }

    /**
     * 流式模型注册器。
     *
     * <p>它和 {@link ChatModelRegister} 收同样的三个参数 —— 这不是对称的美观问题，
     * 是**功能要求**：不传 recorder 进去，流式调用的 token 用量就不会被统计，
     * 而流式恰恰是本项目的主场景。
     */
    @Bean
    @ConditionalOnProperty(prefix = "ai.chat", name = "enabled",
            havingValue = "true", matchIfMissing = true)
    @ConditionalOnMissingBean
    public StreamingChatModelRegister streamingChatModelRegister(
            ChatModelProperties properties,
            ObjectProvider<TokenUsageRecorder> recorderProvider) {
        return new StreamingChatModelRegister(properties, serviceName, recorderProvider.getIfAvailable());
    }

    @Bean
    @ConditionalOnProperty(prefix = "ai.embed", name = "enabled",
            havingValue = "true", matchIfMissing = true)
    @ConditionalOnMissingBean
    public EmbeddingModelRegister embeddingModelRegister(EmbeddingModelProperties properties) {
        return new EmbeddingModelRegister(properties);
    }

    // ==================================================== 用户上下文

    /**
     * 把 {@code X-User-Id} 请求头写进 {@link com.best.ai_common.context.AiUserContext}，
     * 供 {@code TokenUsageListener} 记录"这次调用是谁发起的"。
     *
     * <p>只有 servlet web 应用才需要它 —— 非 web 服务引了这个 jar 也不该被拖上 MVC 依赖。
     */
    @Bean
    @ConditionalOnMissingBean
    @ConditionalOnWebApplication(type = ConditionalOnWebApplication.Type.SERVLET)
    public AiUserContextInterceptor aiUserContextInterceptor() {
        return new AiUserContextInterceptor();
    }

    // ==================================================== token 台账

    /**
     * 台账落库。单独一个嵌套配置类，是因为它有一组自己的前提条件
     * （有 MyBatis-Plus、有 DataSource），混在外层会让条件语义变模糊。
     */
    @Configuration(proxyBeanMethods = false)
    @ConditionalOnClass({BaseMapper.class, DataSource.class})
    @ConditionalOnBean(DataSource.class)
    @MapperScan("com.best.ai_common.metrics.db")
    static class TokenUsageDbConfig {

        @Bean
        @ConditionalOnMissingBean
        public TokenUsageRecorder tokenUsageRecorder(AiTokenUsageMapper mapper) {
            return new DbTokenUsageRecorder(mapper);
        }
    }

    // ==================================================== MCP 工具

    /**
     * MCP 客户端与工具提供者。
     *
     * <p>注意 {@code ai.mcp.enabled} 是**装配级**开关：它为 false 时这两个 Bean 根本不存在，
     * 所以业务侧注入 {@code McpToolProvider} 必须可空（或干脆别注入）。
     */
    @Configuration(proxyBeanMethods = false)
    @ConditionalOnProperty(prefix = "ai.mcp", name = "enabled", havingValue = "true")
    static class McpConfig {

        @Bean
        @ConditionalOnMissingBean
        public McpClientRegister mcpClientRegister(McpProperties properties) {
            return new McpClientRegister(properties);
        }

        @Bean
        @ConditionalOnMissingBean
        public McpToolProvider mcpToolProvider(McpClientRegister register) {
            return McpToolProvider.builder()
                    .mcpClients(register.all())
                    .failIfOneServerFails(false)
                    .build();
        }
    }
}
```

> **`@ConditionalOnMissingBean` 不带参数**（如 `chatModelRegister` 上那个）是按**方法返回类型**推断的，
> 和你原来写的一致 —— 使用方声明同类型 Bean 就能覆盖，这是刻意留的口子。

# 二、P0-2 · 流式模型挂上 token 计量

## 5. 改 `ai-common/.../register/StreamingChatModelRegister.java`

**整个文件替换**：

```java
package com.best.ai_common.register;

import com.best.ai_common.metrics.TokenUsageListener;
import com.best.ai_common.metrics.TokenUsageRecorder;
import com.best.ai_common.properties.ChatModelProperties;
import dev.langchain4j.model.chat.StreamingChatModel;
import dev.langchain4j.model.chat.listener.ChatModelListener;
import dev.langchain4j.model.openai.OpenAiStreamingChatModel;

import java.util.List;

/**
 * 流式对话模型注册器。
 *
 * <p><b>它和 {@link ChatModelRegister} 收完全相同的三个参数，这是刻意的。</b>
 * 之前这里只收 properties，于是流式调用的 token 用量一条都进不了台账 ——
 * 而流式是本项目的主场景（页面上的对话全走这条路）。
 *
 * <p>{@code StreamingChatModel} 用的是和阻塞式<b>同一个</b> {@link ChatModelListener} 接口，
 * 没有专用版本，所以监听器可以原样复用。
 *
 * <p><b>一个前提：能不能拿到 usage 取决于上游。</b>
 * OpenAI 协议的流式响应默认<b>不返回</b> usage，需要请求带
 * {@code stream_options: {"include_usage": true}}，否则最后一个 chunk 里也没有用量。
 * 拿不到时 {@code TokenUsageListener} 会直接 return（它判了 null），
 * 不会报错 —— 表现为台账里流式记录数偏少或为零。遇到这种情况去查网关是否透传了 usage。
 */
public class StreamingChatModelRegister extends ModelRegister<StreamingChatModel> {

    private final ChatModelProperties properties;

    /** 来源服务名，标记 token 用量属于哪个服务 */
    private final String serviceName;

    private final TokenUsageRecorder recorder;

    public StreamingChatModelRegister(ChatModelProperties properties,
                                      String serviceName,
                                      TokenUsageRecorder recorder) {
        this.properties = properties;
        this.serviceName = serviceName;
        this.recorder = recorder;
    }

    @Override
    protected StreamingChatModel create(String profile) {
        ChatModelProperties.Endpoint endpoint = properties.getEndpoint(profile);

        // recorder 为 null 时用空列表 —— 保证"没有数据源"不会让流式对话起不来
        List<ChatModelListener> listeners = recorder == null ? List.of()
                : List.of(new TokenUsageListener(serviceName, profile, endpoint.modelName(), recorder));

        return OpenAiStreamingChatModel.builder()
                .baseUrl(endpoint.baseUrl())
                .apiKey(endpoint.apiKey())
                .modelName(endpoint.modelName())
                .temperature(endpoint.temperature() != null ? endpoint.temperature() : properties.temperature())
                .maxTokens(endpoint.maxTokens() != null ? endpoint.maxTokens() : properties.maxTokens())
                .timeout(endpoint.timeout() != null ? endpoint.timeout() : properties.timeout())
                .listeners(listeners)
                .build();
    }

    @Override
    public String DefaultProfile() {
        return properties.profile();
    }
}
```

> **注意构造器签名变了**（从 1 个参数变成 3 个）。
> 调用点只有一处，就是上面第 1 项里那个 `streamingChatModelRegister` Bean —— 已经是新写法了。
> 如果你有单元测试直接 `new StreamingChatModelRegister(properties)`，也要跟着改。

```java
package com.best.ai_memory.user.db;

import java.nio.ByteBuffer;
import java.nio.FloatBuffer;

/**
 * {@code float[]} 与 BLOB 之间的编解码。
 *
 * <p>放在 db 包而不是 user 包：它做的是<b>存储格式</b>的转换，不是领域概念。
 * 上一个版本它住在 {@code user} 顶层，但唯一的引用者是
 * {@link FloatArrayTypeHandler} —— 只被一个子包用，就该住进那个子包。
 *
 * <p>{@code UserMemory} 里的 {@code float[] embedding} 字段对调用方是透明的，
 * 靠的就是 {@link FloatArrayTypeHandler} 在中间转换，
 * 所以调用方（检索、抽取）完全不需要知道 byte 序、字节数这些细节。
 *
 * <p><b>字节序</b>：{@link ByteBuffer#allocate(int)} 用的是<b>大端</b>（Big Endian，网络字节序）。
 * 如果以后有别的语言（Python / Go）读这张表，要按大端解，否则数值全错。
 */
public final class VectorCodec {

    private VectorCodec(){}

    /**
     * 把向量编码成字节。
     *
     * @return null 表示"没有向量"（入参为 null）。注意它和 decode 的约定是<b>不对称</b>的：
     *         编码 null 得到 null，但解码 null 得到长度为 0 的数组（见下）
     */
    public static byte[] encode(float[] vector){
        if (vector == null){
            return null;
        }
        ByteBuffer buffer = ByteBuffer.allocate(vector.length * Float.BYTES);
        buffer.asFloatBuffer().put(vector);
        return buffer.array();
    }

    /**
     * 把字节解码成向量。
     *
     * <p><b>入参为 null 或空时返回的是空数组，不是 null。</b>
     * 也就是说库里 {@code embedding} 列为 NULL 时，实体上拿到的是 {@code float[0]}。
     * 检索侧已经处理过这一点（判了 {@code length == 0}），但自己写测试时要知道。
     */
    public static float[] decode(byte[] bytes){
        if(bytes == null || bytes.length == 0){
            return new float[0];
        }
        FloatBuffer floatBuffer = ByteBuffer.wrap(bytes).asFloatBuffer();
        float[] vector = new float[floatBuffer.remaining()];
        floatBuffer.get(vector);
        return vector;
    }
}
```

```java
package com.best.ai_memory.user.db;

import org.apache.ibatis.type.BaseTypeHandler;
import org.apache.ibatis.type.JdbcType;
import org.apache.ibatis.type.MappedTypes;

import java.sql.CallableStatement;
import java.sql.PreparedStatement;
import java.sql.ResultSet;
import java.sql.SQLException;

/**
 * {@code float[]} ←→ BLOB 的 MyBatis 类型处理器。
 *
 * <p>为什么值得单独一个类，而不是在每个调用点手写 VectorCodec：
 * 那样的话"float[] 存成什么格式"会散落到 insert、查询映射、测试桩三处。
 * 收进 TypeHandler 之后它只出现在一个地方，而且 {@code UserMemory} 的字段类型
 * 可以是干净的 {@code float[]}。
 *
 * <p>注意：这个类的全限定名被两个地方<b>以字符串形式</b>引用，改包名时要手工同步 ——
 * ① {@code UserMemory} 上的 {@code @TableField(typeHandler = FloatArrayTypeHandler.class)}
 *    （这个是用 class 引用，IDE 会自动改）
 * ② {@code UserMemoryMapper.xml} 里的 {@code typeHandler="com.best.ai_memory.user.db.FloatArrayTypeHandler"}
 *    （这个是字符串，IDE <b>不会</b>改）
 *
 * <p>本次它<b>没有</b>挪包，所以上面两处都不用动。列在这里是为了提醒：以后要挪它，两处都得改。
 */
@MappedTypes(float[].class)
public class FloatArrayTypeHandler extends BaseTypeHandler<float[]> {

    @Override
    public void setNonNullParameter(PreparedStatement ps, int i, float[] parameter, JdbcType jdbcType) throws SQLException {
        ps.setBytes(i, VectorCodec.encode(parameter));
    }

    @Override
    public float[] getNullableResult(ResultSet rs, String columnName) throws SQLException {
        return VectorCodec.decode(rs.getBytes(columnName));
    }

    @Override
    public float[] getNullableResult(ResultSet rs, int columnIndex) throws SQLException {
        return VectorCodec.decode(rs.getBytes(columnIndex));
    }

    @Override
    public float[] getNullableResult(CallableStatement cs, int columnIndex) throws SQLException {
        return VectorCodec.decode(cs.getBytes(columnIndex));
    }
}
```

> **删掉了 `import com.best.ai_memory.user.db.VectorCodec;`** —— 因为现在它和
> `FloatArrayTypeHandler` 同包，不需要 import 了。这是本次唯一的变化。

```java
package com.best.ai_common.metrics.db;

import com.baomidou.mybatisplus.annotation.IdType;
import com.baomidou.mybatisplus.annotation.TableId;
import com.baomidou.mybatisplus.annotation.TableName;
import lombok.Data;

import java.time.LocalDateTime;

/**
 * {@code ai_token_usage} 表的实体。
 *
 * <p>放在 db 包而不是 metrics 包：它的引用者全在 db 包里
 * （{@link AiTokenUsageMapper}、{@link DbTokenUsageRecorder}）。
 * 上一个版本它住在 {@code metrics} 顶层 —— 实体在父包、它的 Mapper 在子包，
 * 层级是反的，从 {@code metrics} 顶层看过去完全想不到它只属于 db 这一层。
 *
 * <p><b>为什么是 class 不是 record：</b>MyBatis-Plus 的 {@code IdType.AUTO}
 * 要在 insert 之后把自增主键<b>回填</b>到实体上，record 没有 setter，
 * {@code MetaObject.setValue} 会抛 {@code ReflectionException}。
 * （同一个原因，{@code UserMemory} 也是 class。）
 */
@Data
@TableName("ai_token_usage")
public class AiTokenUsageEntity {

    @TableId(type = IdType.AUTO)
    private Long id;

    /** 这条用量是谁产生的。取自请求头 {@code X-User-Id}，取不到时写 anonymous */
    private String userId;

    /** 来源服务名，用于多服务共用一张表后按服务维度统计 */
    private String serviceName;

    /** 用的哪个模型档位 */
    private String profile;

    /** 真实模型名 */
    private String modelName;

    private Integer inputTokens;

    private Integer outputTokens;

    private Integer totalTokens;

    /** 落库时间，带毫秒 */
    private LocalDateTime occurredAt;
}
```

## 12. 改 `ai-common/.../metrics/db/DbTokenUsageRecorder.java`

**整个文件替换**（只有 import 组变了）：

```java
package com.best.ai_common.metrics.db;

import com.best.ai_common.context.AiUserContext;
import com.best.ai_common.metrics.TokenUsageRecord;
import com.best.ai_common.metrics.TokenUsageRecorder;
import lombok.extern.slf4j.Slf4j;
import org.springframework.beans.factory.DisposableBean;

import java.time.LocalDateTime;
import java.time.ZoneId;
import java.util.ArrayList;
import java.util.List;
import java.util.concurrent.BlockingQueue;
import java.util.concurrent.LinkedBlockingQueue;
import java.util.concurrent.TimeUnit;

/**
 * 把 token 用量异步批量写入数据库。
 *
 * <p>核心动机：{@code record()} 跑在模型回调线程上，而落库是慢的。
 * 这两件事必须解开，解开的方式就是队列 + 独立消费线程。
 *
 * <p><b>有界队列是刻意的。</b>{@link LinkedBlockingQueue} 的默认容量是
 * {@code Integer.MAX_VALUE}（等于无界），模型网关抖动时回调堆积会把内存吃光。
 * 有界之后只会丢数据，不会 OOM —— 而统计数据的价值远小于业务可用性。
 */
@Slf4j
public class DbTokenUsageRecorder implements TokenUsageRecorder, DisposableBean {

    /** 队列容量：持续积压到该值说明落库跟不上，需要告警 */
    private static final int QUEUE_CAPACITY = 10_000;

    /** 单批最大条数 */
    private static final int BATCH_SIZE = 200;

    /** 队列空闲时的等待间隔，避免空转 */
    private static final long IDLE_WAIT_MS = 1000L;

    private final AiTokenUsageMapper mapper;

    private final BlockingQueue<TokenUsageRecord> queue = new LinkedBlockingQueue<>(QUEUE_CAPACITY);

    private final Thread worker;

    private volatile boolean running = true;

    public DbTokenUsageRecorder(AiTokenUsageMapper mapper) {
        this.mapper = mapper;
        this.worker = new Thread(this::consume, "token-usage-writer");
        // 守护线程：主线程退出时不阻塞 JVM 关闭。
        // 真正的收尾靠下面的 destroy()，不靠 daemon 语义。
        this.worker.setDaemon(true);
        this.worker.start();
    }

    @Override
    public void record(TokenUsageRecord record) {
        if (!queue.offer(record)) {
            // 队列满说明落库严重滞后：丢弃并告警，保证不影响业务请求
            log.warn("token 用量队列已满({})，丢弃记录: userId={} profile={} totalTokens={}",
                    QUEUE_CAPACITY, record.userId(), record.profile(), record.totalTokens());
        }
    }

    private void consume() {
        List<TokenUsageRecord> batch = new ArrayList<>(BATCH_SIZE);
        while (running) {
            try {
                // 阻塞等第一条，有数据才继续攒批。
                // 用带超时的 poll 而不是 take()：take() 会永久阻塞，
                // 线程就再也看不到 running = false 了。
                TokenUsageRecord first = queue.poll(IDLE_WAIT_MS, TimeUnit.MILLISECONDS);
                if (first == null) {
                    continue;
                }
                batch.add(first);
                // 把队列中已排队的记录一并取出，凑成一批。drainTo 是非阻塞的，凑不满也不等
                queue.drainTo(batch, BATCH_SIZE - 1);

                writeBatch(batch);
            } catch (InterruptedException e) {
                Thread.currentThread().interrupt();
                break;
            } catch (Exception e) {
                // 落库失败不能拖垮计量线程，也不能影响业务。
                // 注意这里 catch 的是 Exception 而不是 Throwable —— 见类尾说明
                log.error("token 用量入库失败，丢弃 {} 条", batch.size(), e);
            } finally {
                batch.clear();
            }
        }
    }

    private void writeBatch(List<TokenUsageRecord> records){
        if(records.isEmpty()){
            return;
        }
        mapper.insertBatch(records.stream().map(DbTokenUsageRecorder::toEntity).toList());
    }

    /**
     * 容器关闭时把队列里剩下的刷出去。
     *
     * <p>顺序很重要：先停线程（{@code running = false} + {@code join}），
     * 再排空队列。反过来的话消费线程会和新起的这段代码抢同一条队列。
     *
     * <p>{@code join(5_000)} 设了上限 —— 别让停机变成卡住。
     * 超时未完成就进入下面的排空逻辑，尽力而为。
     */
    @Override
    public void destroy() throws Exception {
        running = false;
        worker.join(5_000);

        List<TokenUsageRecord> remaining = new ArrayList<>(BATCH_SIZE);
        queue.drainTo(remaining);
        if (remaining.isEmpty()) {
            return;
        }
        try {
            writeBatch(remaining);
            log.info("退出前刷写 token 用量 {} 条", remaining.size());
        } catch (Exception e) {
            log.error("退出前刷写 token 用量失败，丢失 {} 条", remaining.size(), e);
        }
    }

    private static AiTokenUsageEntity toEntity(TokenUsageRecord record) {
        // 同包，所以不需要 import AiTokenUsageEntity
        AiTokenUsageEntity entity = new AiTokenUsageEntity();
        // 兜底：保证 user_id 不为 null，否则按用户查询会漏数据
        entity.setUserId(record.userId() == null ? AiUserContext.ANONYMOUS : record.userId());
        // 兜底：保证 service_name 不为 null，否则按服务统计会漏数据
        entity.setServiceName(record.serviceName() == null ? TokenUsageRecord.UNKNOWN_SERVICE : record.serviceName());
        entity.setProfile(record.profile());
        entity.setModelName(record.modelName());
        entity.setInputTokens(record.inputTokens());
        entity.setOutputTokens(record.outputTokens());
        entity.setTotalTokens(record.totalTokens());
        entity.setOccurredAt(LocalDateTime.ofInstant(record.occurredAt(), ZoneId.systemDefault()));
        return entity;
    }
}
```

> 变化点：**删掉 `import com.best.ai_common.metrics.db.AiTokenUsageEntity;`**（同包了）。
> 其余一字未改，只补了注释。
