## 2. EventAssembler 完整代码

**文件路径：`/Users/best/project/ai_platform/ai-agentscope/src/main/java/com/best/ai_agentscope/ch03_message_event/EventAssembler.java`**

```java
package com.best.ai_agentscope.ch03_message_event;

import io.agentscope.core.event.AgentEvent;
import io.agentscope.core.event.AgentResultEvent;
import io.agentscope.core.event.AgentStartEvent;
import io.agentscope.core.event.ModelCallEndEvent;
import io.agentscope.core.event.TextBlockDeltaEvent;
import io.agentscope.core.event.ToolCallDeltaEvent;
import io.agentscope.core.event.ToolCallStartEvent;
import io.agentscope.core.event.ToolResultEndEvent;
import io.agentscope.core.message.ToolResultState;
import java.util.LinkedHashMap;
import java.util.Map;

/**
 * 从事件流重建一条回复。
 *
 * 事件的关联键是三级：replyId（哪次回复）→ blockId（哪个内容块）/ toolCallId（哪次工具调用）。
 * 同一个 blockId 的 delta 按到达顺序拼接，就是前端要显示的内容。
 */
public class EventAssembler {

    private final Map<String, StringBuilder> textByBlock = new LinkedHashMap<>();
    private final Map<String, ToolBuffer> tools = new LinkedHashMap<>();
    private String replyId;
    private int modelCalls = 0;
    private String resultEventText;
    private boolean resultEventSeen = false;

    public void accept(AgentEvent event) {
        if (event instanceof AgentStartEvent start) {
            this.replyId = start.getReplyId();
        } else if (event instanceof TextBlockDeltaEvent delta) {
            textByBlock.computeIfAbsent(delta.getBlockId(), k -> new StringBuilder())
                    .append(delta.getDelta());
        } else if (event instanceof ToolCallStartEvent start) {
            tools.computeIfAbsent(start.getToolCallId(),
                    k -> new ToolBuffer(start.getToolCallName()));
        } else if (event instanceof ToolCallDeltaEvent delta) {
            ToolBuffer buffer = tools.get(delta.getToolCallId());
            if (buffer != null) {
                buffer.args.append(delta.getDelta());
            }
        } else if (event instanceof ToolResultEndEvent end) {
            ToolBuffer buffer = tools.get(end.getToolCallId());
            if (buffer != null) {
                buffer.state = end.getState();
            }
        } else if (event instanceof ModelCallEndEvent end) {
            modelCalls++;
        } else if (event instanceof AgentResultEvent result) {
            resultEventSeen = true;
            resultEventText = result.getResult().getTextContent();
        }
    }

    /** 汇总本次重建的结果 */
    public Map<String, Object> summary() {
        String reconstructed = text();
        Map<String, Object> result = new LinkedHashMap<>();
        result.put("replyId", replyId);
        result.put("text", reconstructed);
        result.put("modelCalls", modelCalls);
        result.put("tools", tools.values().stream()
                .map(t -> Map.<String, Object>of(
                        "name", t.name,
                        "args", t.args.toString(),
                        "state", String.valueOf(t.state)))
                .toList());
        result.put("resultEventSeen", resultEventSeen);
        if (resultEventSeen) {
            result.put("resultEventText", resultEventText);
            result.put("matchesResultEvent", reconstructed.equals(resultEventText));
        }
        return result;
    }

    private String text() {
        StringBuilder all = new StringBuilder();
        for (StringBuilder block : textByBlock.values()) {
            if (all.length() > 0) {
                all.append('\n');
            }
            all.append(block);
        }
        return all.toString();
    }

    private static final class ToolBuffer {
        private final String name;
        private final StringBuilder args = new StringBuilder();
        private ToolResultState state;

        private ToolBuffer(String name) {
            this.name = name;
        }
    }
}
```

**逐段讲为什么**：

| 代码 | 为什么这样写 |
|---|---|
| 按 `blockId` 分桶拼文本 | 一次回复可能有多个文本块（正文 + 思考块…）。`blockId` 是 replyId 作用域内的关联键，同一次回复里所有 `TEXT_BLOCK_DELTA` 靠它归并。**不按块分桶直接全 append 也能凑出文本，但多块交错时就乱了**——现在没有工具所以看不出来，第 4 章接上工具后工具结果和正文交错，分桶是唯一正确的做法 |
| `computeIfAbsent(...).append(...)` | 标准的分桶累积。`LinkedHashMap` 保证块的**出现顺序**——前端渲染顺序要稳定 |
| `ToolCallStart/Delta/End` 用 `toolCallId` 关联 | 工具调用的事件三级键。`Delta` 里是 **JSON 参数片段**（`getDelta()` 返回字符串），要拼接才是完整入参——流式工具调用的参数是一点点吐出来的 |
| `ToolResultEndEvent.getState()` | 工具结果终态（`SUCCESS` / `ERROR` / `DENIED` / `INTERRUPTED`…）。本章还看不到工具事件，这段代码是给第 4 章预留的，先建好心智 |
| `AgentResultEvent` 单独捕获 | ⚠️ **实测发现，文档没写**：2.0.4 的事件流里有 `AGENT_RESULT`，它直接携带最终 `Msg`（javap：`getResult()`）。这是「事件流 → Msg」的官方通道。所以本章的检查点能做一个**硬断言**：重建文本 == 结果事件的文本（见自查清单实验 2） |
| 工具部分用 `Map.of(...)` | 不可变快照，summary 可以安全传出。`state` 可能为 null（工具没结束就流断了），`String.valueOf` 兜住 |

## 3. StreamController 完整代码

**文件路径：`/Users/best/project/ai_platform/ai-agentscope/src/main/java/com/best/ai_agentscope/ch03_message_event/StreamController.java`**

```java
package com.best.ai_agentscope.ch03_message_event;

import com.fasterxml.jackson.databind.ObjectMapper;
import io.agentscope.core.agent.RuntimeContext;
import io.agentscope.core.event.AgentEvent;
import io.agentscope.core.event.TextBlockDeltaEvent;
import io.agentscope.core.event.ToolCallStartEvent;
import io.agentscope.core.event.ToolResultEndEvent;
import io.agentscope.core.message.Msg;
import io.agentscope.core.message.UserMessage;
import io.agentscope.harness.agent.HarnessAgent;
import java.util.LinkedHashMap;
import java.util.Map;
import org.springframework.http.MediaType;
import org.springframework.http.codec.ServerSentEvent;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.PostMapping;
import org.springframework.web.bind.annotation.RequestParam;
import org.springframework.web.bind.annotation.RestController;
import reactor.core.publisher.Flux;
import reactor.core.publisher.Mono;

@RestController
public class StreamController {

    private final HarnessAgent.Builder agentBuilder;
    private final ObjectMapper objectMapper;

    // 注入第 1 章的 builder bean（同一个 note-taker agent）
    public StreamController(HarnessAgent.Builder agentBuilder, ObjectMapper objectMapper) {
        this.agentBuilder = agentBuilder;
        this.objectMapper = objectMapper;
    }

    /** SSE 流式端点：边生成边推事件，流末追加重建结果 */
    @GetMapping(value = "/stream", produces = MediaType.TEXT_EVENT_STREAM_VALUE)
    public Flux<ServerSentEvent<String>> stream(@RequestParam String sessionId,
                                                @RequestParam String message) {
        RuntimeContext ctx = RuntimeContext.builder()
                .userId("alice")
                .sessionId(sessionId)
                .build();
        EventAssembler assembler = new EventAssembler();
        return Flux.using(
                        agentBuilder::build,
                        agent -> agent.streamEvents(new UserMessage(message), ctx),
                        HarnessAgent::close)
                .doOnNext(assembler::accept)
                .map(this::toSse)
                .concatWith(Mono.fromCallable(() -> toSse("assembled", assembler.summary())));
    }

    /** Msg 解剖台：一次 call 之后，看看回复消息的里层结构 */
    @PostMapping("/msg-anatomy")
    public Map<String, Object> anatomy(@RequestParam String message) {
        try (HarnessAgent agent = agentBuilder.build()) {
            RuntimeContext ctx = RuntimeContext.builder()
                    .userId("alice")
                    .sessionId("anatomy")
                    .build();
            Msg reply = agent.call(new UserMessage(message), ctx).block();
            Map<String, Object> result = new LinkedHashMap<>();
            result.put("id", reply.getId());
            result.put("role", String.valueOf(reply.getRole()));
            result.put("blockTypes", reply.getContent().stream()
                    .map(b -> b.getClass().getSimpleName()).toList());
            result.put("text", reply.getTextContent());
            result.put("generateReason", String.valueOf(reply.getGenerateReason()));
            result.put("timestamp", reply.getTimestamp());
            result.put("usageInputTokens", reply.getUsage() == null ? null : reply.getUsage().getInputTokens());
            result.put("usageOutputTokens", reply.getUsage() == null ? null : reply.getUsage().getOutputTokens());
            return result;
        }
    }

    private ServerSentEvent<String> toSse(AgentEvent event) {
        Map<String, Object> payload = new LinkedHashMap<>();
        payload.put("type", event.getType().name());
        payload.put("id", event.getId());
        if (event.getSource() != null) {
            payload.put("source", event.getSource());
        }
        if (event instanceof TextBlockDeltaEvent delta) {
            payload.put("delta", delta.getDelta());
        } else if (event instanceof ToolCallStartEvent start) {
            payload.put("toolName", start.getToolCallName());
        } else if (event instanceof ToolResultEndEvent end) {
            payload.put("state", String.valueOf(end.getState()));
        }
        return toSse(event.getType().name().toLowerCase(), payload);
    }

    private ServerSentEvent<String> toSse(String name, Object payload) {
        try {
            return ServerSentEvent.<String>builder()
                    .data(objectMapper.writeValueAsString(payload)).build();
        } catch (Exception e) {
            return ServerSentEvent.<String>builder().data("{}").build();
        }
    }
}
```

**逐段讲为什么**：

| 代码 | 为什么这样写 |
|---|---|
| `Flux.using(builder::build, agent -> agent.streamEvents(...), HarnessAgent::close)` | **流式场景的实例生命周期正解**。`Flux.using` 在订阅时创建实例、流结束/报错/取消时 close。⚠️ 第 1 章的 `try-with-resources` 在这里**不能用**——那个写法会在方法返回时就关闭 agent，而流还没订阅。官方文档点名了这个坑 |
| `doOnNext(assembler::accept)` 旁路累积 | assembler 不改变流，只是「偷看」每个事件。`.map(toSse)` 在前或在后都行，但**必须都在 `Flux.using` 的链上**——close 发生在整条链结束后 |
| `concatWith(Mono.fromCallable(...))` 追加重建结果 | `concatWith` 保证在事件流**完成后**才发 `assembled` 事件——此时 assembler 已吃满全部事件。`fromCallable` 惰性求值，订阅时才调 `summary()` |
| assembler 是**方法内局部变量** | 每个请求一个。它是可变的（分桶 map），**绝不能**提成 bean——和第 2 章 fallback 模型同一条纪律 |
| `produces = TEXT_EVENT_STREAM_VALUE` | MVC 认识这个 media type：返回 `Flux<ServerSentEvent>` 时自动按 SSE 协议写给客户端。**不需要 WebFlux** |
| `ServerSentEvent.builder().data(...)` 不带 `name()` | ⚠️ 实测：Spring 的 `ServerSentEvent.Builder` **没有 `name(String)` 方法**（我第一版写了，编译不过）。事件类型放在 JSON payload 的 `type` 字段里，前端自己解 |
| `ObjectMapper` 构造注入 | Spring Boot 自动装配的那个（带 JavaTimeModule 等模块）。⚠️ 别自己 new——项目在 ai-orchestrator 上已经栽过「裸 mapper 缺 JavaTimeModule」的坑（43 号修订记录） |
| `/msg-anatomy` 用 `try-with-resources + block()` | 阻塞端点回到第 1 章形态——一次性拿完整结果，不流式。两种端点形态对照着看：**要过程用流，要结果用 block** |
| `reply.getUsage() == null ? null : ...` | 流式 usage 可能拿不到（第 2 章实测过）。`Map.of` 不接受 null value，所以要么判空要么用 `LinkedHashMap.put`——这里是后者 |
| `blockTypes` 用 `getClass().getSimpleName()` | 一条回复的「积木清单」。纯文本问答通常只有 `TextBlock`；第 4 章之后会出现 `ToolUseBlock` / `ToolResultBlock` |

## 4. 三个必须建立的心智模型

**① `Msg` 是「一轮完整对话」，`AgentEvent` 是「这轮对话的直播」。**

一次 `call` / `streamEvents` 内部可以多轮推理 + 多次工具，最终收敛成**恰好一条** assistant `Msg`。事件流是这轮过程的逐帧直播——**两者是同一数据的两种视图**：帧看全了，就能还原消息；消息拿到了，就不用等直播。`AGENT_RESULT` 事件就是框架给你的「官方便捷通道」。

**② 事件的三级关联键，是前端不写乱码的唯一保障。**

```
replyId          这次回复是谁（一次 call 一条）
├── blockId      哪个内容块（文本/思考/数据）
└── toolCallId   哪次工具调用（调用 + 结果共用同一个 id）
```

前端按 `blockId` 建「块组件」、按 `toolCallId` 建「工具卡片」，`replyId` 断开时整体收尾。**不按键归并、按到达顺序 append 的界面，在多块交错时一定花**——第 4 章工具调用和正文交错时就是验收时刻。

**③ 实时事件 ≠ 持久事实。**

`AgentEvent` 是**当次执行的直播流**，断线就没了；`SessionEvent`（Session Log）是**不可变的持久执行事实**，按游标可以重放。前端断线重连的正确姿势是「先取快照、再从游标续读」——这是第 11 章的内容，本章先记住：**不要用重新 `streamEvents` 来补断线期间的内容**，那等于把任务重跑一遍。

```bash
# 流式看一次完整的事件序列（-N 是必须的，否则 curl 缓冲看不到流）
curl -N "http://localhost:8081/stream?sessionId=stream-demo&message=用三句话讲讲Java内存模型"

# Msg 解剖台
```

**预期**：先看到一串 `data: {"type":"AGENT_START",...}` → `MODEL_CALL_START` → 几十个 `TEXT_BLOCK_DELTA`（每个带一小段 `delta`）→ `MODEL_CALL_END`（带 usage）→ `AGENT_END`，最后一条 `assembled` 是重建汇总。把 `delta` 字段按顺序拼起来 = 完整回答。

## 6. 检查点

```bash
curl -N "http://localhost:8081/stream?sessionId=stream-demo&message=你好" | grep -o '"type":"[A-Z_]*"' | sort | uniq -c
```

## 8. 容易写错 / 被改坏的 6 个点

1. **在 `try-with-resources` 里返回未订阅的 `Flux`**——本章最大的坑。方法一返回，agent 就被 close 了，流订阅时拿到的是已关闭实例。**流式场景一律 `Flux.using`**。
2. **`ServerSentEvent.Builder.name()` 不存在**——实测 Spring 没有这个方法。事件类型放 payload 里传。
3. **assembler 提成 bean**——它是 per-request 可变状态。本章它是局部变量，保持这样。
4. **`ObjectMapper` 自己 new**——用注入的那个。裸 mapper 序列化 `Instant` / 时间类型会炸（项目里踩过，43 号修订记录）。
5. **以为事件类型只有文档列的那 28 个**——javap 实测 `AgentEventType` 有 **31 个常量**，多出 `AGENT_RESULT`、`HINT_BLOCK`，`TOOL_RESULT_TEXT_DELTA` / `TOOL_RESULT_DATA_DELTA` 是分开的两个。写 `switch` / `if-else` 分支时**留 default**，别假设穷尽了。
6. **`ModelCallStartEvent` 没有 `getModelName()`**——文档说它「带 modelName」，javap 实测只有 `getReplyId()`。想在 SSE 里显示模型名，从 capabilities 端点拿，别从事件上取。
