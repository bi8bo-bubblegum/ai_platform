# 第一节 · 检索

## 1.1 `ai-memory/.../user/MemoryRecallService.java`

```java
package com.best.ai_memory.user;

import com.best.ai_memory.config.AiMemoryProperties;
import dev.langchain4j.model.embedding.EmbeddingModel;
import lombok.extern.slf4j.Slf4j;

import java.util.Comparator;
import java.util.List;
import java.util.Map;

/**
 * 从用户的全部事实里，挑出和当前问题最相关的几条。
 *
 * <p>为什么检索逻辑单独一个类，不塞进 UserMemoryStore？
 * 因为"取几条、阈值多少、怎么排序"是【业务策略】，而 Store 只管数据访问。
 * 将来把 MySQL 换成向量库时，只要新实现仍然返回
 * {@code List<UserMemory> findByUserId(...)}，这个类一行都不用改。
 */
@Slf4j
public class MemoryRecallService {

    private final UserMemoryStore store;
    private final EmbeddingModel embeddingModel;
    private final AiMemoryProperties.User config;

    /** 维度不一致的脏数据计数。只打一次日志，避免刷屏 */
    private volatile boolean dimensionMismatchReported = false;

    public MemoryRecallService(UserMemoryStore store,
                               EmbeddingModel embeddingModel,
                               AiMemoryProperties.User config) {
        this.store = store;
        this.embeddingModel = embeddingModel;
        this.config = config;
    }

    /**
     * @return 按相关度降序的 Top-K 条事实。可能为空，不返回 null
     */
    public List<UserMemory> recall(String userId, String query) {
        if (userId == null || userId.isBlank() || query == null || query.isBlank()) {
            return List.of();
        }

        float[] queryVector;
        try {
            queryVector = embeddingModel.embed(query).content().vector();
        } catch (Exception e) {
            // 检索失败 → 这次对话就当"没有长期记忆"，绝不能因此让对话失败。
            // 用户感知是"助手这次没记住我的偏好"，而不是"助手挂了"。
            log.error("查询向量化失败，本次跳过长期记忆检索, userId={}", userId, e);
            return List.of();
        }

        List<UserMemory> all = store.findByUserId(userId, config.maxFactsPerUser());
        if (all.isEmpty()) {
            return List.of();
        }

        return all.stream()
                .filter(m -> isValid(m, queryVector))
                .map(m -> Map.entry(m, CosineSimilarity.between(queryVector, m.getEmbedding())))
                .filter(e -> e.getValue() >= config.minScore())
                .sorted(Comparator.comparingDouble(
                        (Map.Entry<UserMemory, Double> e) -> e.getValue()).reversed())
                .limit(config.topK())
                .map(Map.Entry::getKey)
                // ⚠️ 关键一步：拿到 Top-K 之后【重新按时间倒序】。
                //
                // 为什么？因为库里可能同时有矛盾的事实 ——
                // 用户半年前说"我在奥斯汀"，上周说"我搬到西雅图了"。
                // 去重只能挡住"太像"的，挡不住这种"相反"的，两条都会留在库里。
                //
                // 按相关度排的话，哪条在前面是随机的。
                // 按时间倒序排，再在注入的文本里明确写"若冲突以靠前的为准"，
                // 模型就能选对。
                //
                // 代价是"最相关的那条"可能不在第一位 —— 但 K 通常只有 5，
                // 而且事实都很短，顺序对模型判断的影响远小于"时间线索"带来的收益。
                .sorted(Comparator.comparing(UserMemory::createdAt).reversed())
                .toList();
    }

    private boolean isValid(UserMemory memory, float[] queryVector) {
        if (memory.getEmbedding() == null || memory.getEmbedding().length == 0) {
            return false;
        }
        if (memory.getEmbedding().length != queryVector.length) {
            // 维度对不上 = 两次用的 embedding 模型不同（多半是 dimensions 被改过）。
            // 这类数据没法比较，直接跳过；但要报出来，否则会表现为
            // "明明库里有几百条，检索永远只返回几条"。
            if (!dimensionMismatchReported) {
                dimensionMismatchReported = true;
                log.error("发现向量维度不一致的记忆（{} vs {}），已跳过。"
                                + "通常是 ai.embed.dimensions 被改过，需要重建历史向量",
                        memory.getEmbedding().length, queryVector.length);
            }
            return false;
        }
        return true;
    }
}
```

# 第二节 · 注入

## 2.1 先搞清一件事：注入的落点

`ContentRetriever` 返回的内容**不是拼进 system message 的**。

LangChain4j 的 `DefaultRetrievalAugmentor` 把它**追加到 UserMessage 的内容前面**。也就是说，模型看到的最后一条用户消息长这样：

```
[关于这位用户的已知信息，按时间倒序，若冲突以靠前的为准]
- 2026-10-09 用户搬到西雅图
- 2026-08-01 用户住在奥斯汀

我今天该看哪几个指标？
```

而不是：

```
system: 你是运筹眼助手... 
        以下是你知道的用户信息：...
user:   我今天该看哪几个指标？
```

**这个差别有实际影响**：

- 好处：检索到的内容和用户问题贴在一起，模型更容易把它当成"回答这个问题需要的材料"
- 代价：**它会参与对话历史**。也就是说，如果你把检索结果拼进用户消息，它会被 `ChatMemory` 存下来——下一轮的历史里就重复出现一遍

第二个问题要认真对待。我们的 `SummarizingChatMemory` 存的是 `assistant.chat(memoryId, message)` 收到的**原始** `message`（框架在 augmentation 之前把它写进 memory 的），所以我们的实现不受影响。但**如果哪天你换成别的记忆实现，要确认它存的是原始消息还是增强后的消息**。

## 2.2 `ai-memory/.../user/UserMemoryContentRetriever.java`

```java
package com.best.ai_memory.user;

import com.best.ai_memory.session.SessionKey;
import dev.langchain4j.data.segment.TextSegment;
import dev.langchain4j.rag.content.Content;
import dev.langchain4j.rag.content.retriever.ContentRetriever;
import dev.langchain4j.rag.query.Query;
import lombok.RequiredArgsConstructor;
import lombok.extern.slf4j.Slf4j;

import java.time.ZoneId;
import java.time.format.DateTimeFormatter;
import java.util.List;

/**
 * 把用户事实作为"检索到的内容"注入对话。
 *
 * <p>为什么用 ContentRetriever 而不是往 ChatMemory 里塞一条 SystemMessage？
 *
 * <p>因为两者的语义不同：
 * - ChatMemory 里的是【这段对话说过的话】，它会占用窗口、会被摘要、会参与裁剪
 * - 检索到的内容每次请求都重新查、用完即弃，不进历史
 *
 * <p>用户事实属于后者 —— 用户三个月前说的偏好，不该占着当前会话的窗口，
 * 而应该"每次都用最新的版本重新查一遍"。
 */
@Slf4j
@RequiredArgsConstructor
public class UserMemoryContentRetriever implements ContentRetriever {

    private static final DateTimeFormatter DATE =
            DateTimeFormatter.ofPattern("yyyy-MM-dd").withZone(ZoneId.systemDefault());

    /**
     * 这段前缀是【写给模型看的指令】，不是给人看的说明。
     * 两句话各有分工：
     * ——"已知信息"告诉它这是什么
     * ——"按时间倒序，若冲突以靠前的为准"解决矛盾事实的取舍
     * 少了第二句，模型面对"住奥斯汀"和"搬到西雅图"会随机选一个。
     */
    private static final String HEADER =
            "[关于这位用户的已知信息，按时间倒序。若其中互相冲突，以靠前的为准]\n";

    private final MemoryRecallService recallService;

    @Override
    public List<Content> retrieve(Query query) {
        String userId = userIdOf(query);
        if (userId == null) {
            return List.of();
        }

        List<UserMemory> memories = recallService.recall(userId, query.text());
        if (memories.isEmpty()) {
            return List.of();
        }

        // ⚠️ 返回【一个】Content，而不是每条事实一个 Content。
        //
        // 两个理由：
        // ① 下游的 ContentAggregator 可能会重新排序（比如接一个 ReRankingContentAggregator），
        //    拆成多条的话，我们精心排的"时间倒序"会被打乱，冲突处理就失效了
        // ② 每条事实只有一句话，拆开注入到 prompt 里会变成一堆孤立的短句，
        //    模型反而不好判断它们之间的关系
        return List.of(Content.from(TextSegment.from(render(memories))));
    }

    /**
     * 从 Query 里把 userId 取出来。
     *
     * <p>这是本篇最"绕"的一处，值得说清楚：
     * ContentRetriever 只拿到一个 Query 对象，而我们的 memoryId 是
     * "userId::sessionId" 拼出来的 —— 所以这里要把它解析回来。
     *
     * <p>为什么要绕这一圈？因为 LangChain4j 的 ChatMemoryProvider 和
     * ContentRetriever 都只认一个 id，没有第二个参数的位置。
     * 把用户信息编码进 memoryId 是唯一不需要引入 ThreadLocal 的做法。
     *
     * <p>（另一条路是在 Filter 里把 userId 放进 ThreadLocal，但那引入了一个
     * "这个回调在哪个线程"的隐含假设 —— 异步路径上会静默失效。）
     */
    private String userIdOf(Query query) {
        Object memoryId = query.metadata() == null ? null : query.metadata().chatMemoryId();
        if (memoryId == null) {
            return null;
        }
        try {
            return SessionKey.parse(String.valueOf(memoryId)).userId();
        } catch (IllegalArgumentException e) {
            // memoryId 格式不对说明装配错了。这里只 warn 不抛：
            // 抛出去会让整次对话失败，而"没有长期记忆"只是一个降级，
            // 不该把能正常回答的对话变成 500。
            log.warn("memoryId 格式不符合 userId::sessionId，本次跳过长期记忆检索: {}", memoryId);
            return null;
        }
    }

    private String render(List<UserMemory> memories) {
        StringBuilder sb = new StringBuilder(HEADER);
        for (UserMemory m : memories) {
            sb.append("- ")
                    .append(DATE.format(m.getCreatedAt()))
                    .append(' ')
                    .append(m.getContent())
                    .append('\n');
        }
        return sb.toString();
    }
}
```

## 2.3 改 `assistant-demo/.../config/AssistantConfig.java`

装配在助手侧（04 定下来的），所以这一篇要动的是**业务模块**，不是 AI-Memory。加一个参数、加三行：

```java
package com.best.assistant_demo.config;

import com.best.ai_common.register.ChatModelRegister;
import com.best.ai_common.register.StreamingChatModelRegister;
import com.best.assistant_demo.assistant.ChatAssistant;
import dev.langchain4j.memory.chat.ChatMemoryProvider;
import dev.langchain4j.model.chat.ChatModel;
import dev.langchain4j.model.chat.StreamingChatModel;
import dev.langchain4j.rag.RetrievalAugmentor;
import dev.langchain4j.service.AiServices;
import org.springframework.beans.factory.ObjectProvider;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;

@Configuration(proxyBeanMethods = false)
public class AssistantConfig {

    @Bean
    public ChatAssistant chatAssistant(ChatModelRegister chatModelRegister,
                                       StreamingChatModelRegister streamingRegister,
                                       ChatMemoryProvider chatMemoryProvider,
                                       // ⚠️ 用 ObjectProvider 而不是直接注入 RetrievalAugmentor：
                                       // 关掉 ai.memory.user.enabled 时这个 Bean 根本不存在，
                                       // 直接注入会让【整个助手服务启动失败】——
                                       // 一个可选能力把核心功能拖下水，代价太大。
                                       ObjectProvider<RetrievalAugmentor> augmentorProvider) {

        ChatModel chatModel = chatModelRegister.getDefault();
        StreamingChatModel streamingChatModel = streamingRegister.getDefault();

        AiServices<ChatAssistant> builder = AiServices.builder(ChatAssistant.class)
                .chatModel(chatModel)
                .streamingChatModel(streamingChatModel)
                .chatMemoryProvider(chatMemoryProvider);

        // 长期记忆是可选能力：没有 augmentor 时，
        // 会话记忆和流式输出照常工作，只是不会注入用户事实。
        RetrievalAugmentor augmentor = augmentorProvider.getIfAvailable();
        if (augmentor != null) {
            builder.retrievalAugmentor(augmentor);
        }

        return builder.build();
    }
}
```

> `AiServices.builder(...)` 返回的就是 `AiServices<T>` 本身（它既是 builder 也是工厂），
> 所以可以先赋给变量、按条件补配置、最后 `.build()`。

**注意这里体现出来的那个好处**：装配点在自己手上，加 `retrievalAugmentor` 就是在这一个文件里加个参数 + 三行条件。
如果装配器当初留在 AI-Memory，这个改动会变成"改 AI-Memory 的公共 API + 所有助手跟着改签名"。

## 改 `ai-memory/.../config/AiMemoryAutoConfiguration.java`

在 `chatMemoryProvider` 那个 Bean 之后，加一个嵌套配置类。

**注意这里没有 `memoryAwareAssistantFactory` 了** —— 04 已经把这个 Bean 拿掉，装配搬去了助手侧。
AI-Memory 在这一篇里新增的全部内容，就是下面这些「能力」Bean，一个装配器都没有。

```java
    // ================================================ 用户记忆

    @Configuration(proxyBeanMethods = false)
    @ConditionalOnClass({BaseMapper.class, DataSource.class})
    @ConditionalOnBean(DataSource.class)
    @MapperScan("com.best.ai_memory.user.db")
    @ConditionalOnProperty(prefix = "ai.memory.user", name = "enabled",
            havingValue = "true", matchIfMissing = true)
    static class UserMemoryConfig {

        @ConditionalOnMissingBean

            // 默认的 queryTransformer 是恒等变换 —— 也就是"不改写用户问题直接检索"。
            // 等你发现"用户问题里有代词，检索不准"时，再来换 CompressingQueryTransformer。
            return DefaultRetrievalAugmentor.builder()
                    .contentRetriever(retriever)
                    .build();
```

### ⚠️ 同时要改**外层的** `@AutoConfiguration`

这是最容易漏、而且漏了**不报错**的一处。`AiMemoryAutoConfiguration` 类上的注解要加上 `after`：

```java
@AutoConfiguration(after = DataSourceAutoConfiguration.class)
@EnableConfigurationProperties(AiMemoryProperties.class)
public class AiMemoryAutoConfiguration {
```

为什么：`@ConditionalOnBean(DataSource.class)` 的结果取决于**求值那一刻**容器里有没有 `DataSource` Bean。
不在 `DataSourceAutoConfiguration` 之后求值，条件就会在 DataSource 注册之前被评估 → **永远 false** →
整个 `UserMemoryConfig` 静默不装载。

症状是：应用正常启动，但 `NoSuchBeanDefinitionException: UserMemoryStore`（或者更隐蔽的——
某个注入 `UserMemoryStore` 的地方报错）。而 `TokenUsageDbAutoConfiguration` 里用的是同一个套路，
你可以对照着看。

> 顺带说 `@ConditionalOnClass({BaseMapper.class, DataSource.class})` 里的两个类：
> `BaseMapper` 缺了说明没引 MyBatis-Plus；`DataSource` 是 JDK 自带的 `javax.sql.DataSource`，
> 它负责挡住"纯 Redis 的会话记忆场景"（那种情况下没有 JDBC）。
> 两个类条件 + 一个 Bean 条件，是这类"可选数据库功能"的标准三件套。

新增的 import：


（`ChatModelRegister` 前面几节本来就引过了，列在这里只是提醒你别漏。）

> ⚠️ **`@ConditionalOnMissingBean` 和 `@Qualifier` 一起用时的坑**：`retrievalAugmentor` 那个方法里我用 `@Qualifier("userMemoryContentRetriever")` 显式指名。因为将来你可能再加别的 retriever（知识库、工单库），到时候方法参数是一个 `List<ContentRetriever>`，`DefaultRetrievalAugmentor` 就得用 `contentRetrievers(List)` 而不是 `contentRetriever(单个)`。现在只有一个，先简单写。

# 第四节 · 让抽取真正跑起来

事实必须在**对话结束之后**被抽取。改 `ChatStreamController`：

```java
// 构造器多注入一个
private final UserMemoryRecorder memoryRecorder;

// 在 stream() 方法里，onCompleteResponse 里加一行：
                .onCompleteResponse(response -> {
                    // ⚠️ 抽取放在这里，不是放在 onPartialResponse。
                    //
                    // 两个理由：
                    // ① 只有流结束了才有完整的助手回复，半个回复抽出来的事实是错的
                    // ② recordAsync 是异步的，这一行几乎是瞬间返回的，
                    //    不会让用户多等 —— SSE 连接可以立刻关闭
                    // 只传 memoryId —— assistantId / userId / sessionId 由它自己解析。
                    memoryRecorder.recordAsync(
                            memoryId,
                            List.of(UserMessage.from(message),
                                    AiMessage.from(response.aiMessage().text())));
                    if (finished.compareAndSet(false, true)) {
                        emitter.complete();
                    }
                })
```

```java
import dev.langchain4j.data.message.AiMessage;
import dev.langchain4j.data.message.UserMessage;

```

## `test/.../user/MemoryRecallServiceTest.java`

```java
package com.best.ai_memory.user;

import com.best.ai_memory.config.AiMemoryProperties;
import dev.langchain4j.data.embedding.Embedding;
import dev.langchain4j.data.segment.TextSegment;
import dev.langchain4j.model.embedding.EmbeddingModel;
import dev.langchain4j.model.output.Response;
import org.junit.jupiter.api.BeforeEach;
import org.junit.jupiter.api.DisplayName;
import org.junit.jupiter.api.Test;

import java.time.Instant;
import java.util.ArrayList;
import java.util.List;

import static org.assertj.core.api.Assertions.assertThat;

class MemoryRecallServiceTest {

    /** 假 EmbeddingModel：按关键词给出不同的方向 */
    static class KeywordEmbeddingModel implements EmbeddingModel {
        @Override
        public Response<Embedding> embed(String text) {
            if (text.contains("表格") || text.contains("输出")) {
                return Response.from(Embedding.from(new float[]{1f, 0f, 0f}));
            }
            if (text.contains("部门") || text.contains("财务")) {
                return Response.from(Embedding.from(new float[]{0f, 1f, 0f}));
            }
            return Response.from(Embedding.from(new float[]{0f, 0f, 1f}));
        }

        @Override
        public Response<Embedding> embed(TextSegment textSegment) {
            return embed(textSegment.text());
        }

        @Override
        public Response<List<Embedding>> embedAll(List<TextSegment> segments) {
            return Response.from(segments.stream().map(s -> embed(s).content()).toList());
        }
    }

    static class StubStore implements UserMemoryStore {
        final List<UserMemory> data = new ArrayList<>();

        @Override
        public void insert(UserMemory memory) {
            data.add(memory);
        }

        @Override
        public List<UserMemory> findByUserId(String userId, int limit) {
            return List.copyOf(data);
        }

        @Override
        public int countByUserId(String userId) {
            return data.size();
        }

        @Override
        public void deleteOldest(String userId, int count) {
        }

        @Override
        public void deleteAll(String userId) {
            data.clear();
        }
    }

    private StubStore store;
    private MemoryRecallService recallService;

    @BeforeEach
    void setUp() {
        store = new StubStore();
        AiMemoryProperties.User config = new AiMemoryProperties.User(
                true, 5, 0.6, "fast", 0.95, 500);
        recallService = new MemoryRecallService(store, new KeywordEmbeddingModel(), config);
    }

    private void addFact(String content, Instant createdAt) {
        // 直接用假 EmbeddingModel 算向量，模拟"已经存进库里的数据"
        float[] vector = new KeywordEmbeddingModel().embed(content).content().vector();
        UserMemory memory = UserMemory.of("assistant-demo", "u1", content, "s1");
        memory.setEmbedding(vector);
        memory.setCreatedAt(createdAt);   // 覆盖 of() 里的 now()，让排序可断言
        store.data.add(memory);
    }

    @Test
    @DisplayName("问表格相关的问题，只召回表格相关的事实")
    void recallsRelevantOnly() {
        addFact("用户偏好表格输出", Instant.parse("2026-10-01T00:00:00Z"));
        addFact("用户在财务部", Instant.parse("2026-10-02T00:00:00Z"));

        List<UserMemory> result = recallService.recall("u1", "给我个表格看看");

        assertThat(result).hasSize(1);
        assertThat(result.get(0).getContent()).isEqualTo("用户偏好表格输出");
    }

    @Test
    @DisplayName("相关度低于阈值的一条都不返回")
    void belowThresholdReturnsEmpty() {
        addFact("用户在财务部", Instant.parse("2026-10-01T00:00:00Z"));

        // 问一个和"财务/部门"、"表格/输出"都不沾边的问题
        assertThat(recallService.recall("u1", "今天天气怎么样")).isEmpty();
    }

    @Test
    @DisplayName("冲突的事实在结果里按时间倒序 —— 这是模型选对的前提")
    void conflictingFactsAreNewestFirst() {
        addFact("用户住在奥斯汀", Instant.parse("2026-01-01T00:00:00Z"));
        addFact("用户搬到西雅图", Instant.parse("2026-09-01T00:00:00Z"));

        List<UserMemory> result = recallService.recall("u1", "财务部门的事");

        // 两条都会命中（用同一个假向量规则），但必须新在前
        assertThat(result).hasSizeGreaterThanOrEqualTo(2);
        assertThat(result.get(0).getCreatedAt()).isAfter(result.get(1).getCreatedAt());
        assertThat(result.get(0).getContent()).isEqualTo("用户搬到西雅图");
    }

    @Test
    @DisplayName("维度不一致的脏数据被跳过，不会让整次检索挂掉")
    void mismatchedDimensionIsSkipped() {
        addFact("用户在财务部", Instant.parse("2026-10-01T00:00:00Z"));
        // 塞一条 2 维的脏数据（正常是 3 维）
        UserMemory dirty = UserMemory.of("assistant-demo", "u1", "脏数据", "s1");
        dirty.setEmbedding(new float[]{1f, 0f});   // 2 维，正常是 3 维
        store.data.add(dirty);

        List<UserMemory> result = recallService.recall("u1", "财务部门");

        assertThat(result).extracting(UserMemory::getContent).doesNotContain("脏数据");
    }

    @Test
    @DisplayName("空查询、空 userId 直接返回空列表")
    void blankInputsReturnEmpty() {
        addFact("用户在财务部", Instant.parse("2026-10-01T00:00:00Z"));

        assertThat(recallService.recall("", "财务")).isEmpty();
        assertThat(recallService.recall("u1", "")).isEmpty();
        assertThat(recallService.recall(null, "财务")).isEmpty();
    }
```
